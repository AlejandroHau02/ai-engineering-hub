# UX/UI engineering

Use for interfaces, redesigns, usability problems and design-system decisions.

1. Understand user roles, task flows, primary actions, and success criteria.
2. Inspect existing screens, visual language, tokens and component patterns.
3. Design hierarchy around user tasks, not generic sidebars, gradients or metric cards. Challenge unnecessary density with concrete alternatives.
4. Specify loading, empty, error and success states; keyboard use, contrast, legibility, and responsive behavior.
5. Implement coherent components following existing conventions; avoid cosmetic complexity.
6. Inspect rendered states when browser/screenshots are available; otherwise say visual quality remains unverified.
