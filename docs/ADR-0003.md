# ADR-0003 — Skill Scout: inspección antes de cualquier incorporación

**Estado:** Propuesto para v0.3 (primer incremento experimental).

## Contexto

El Hub v0.2 contiene cuatro skills propias y permite sincronizarlas de forma segura. El registro de baselines no confiere confianza a terceros. Queremos identificar capacidades externas sin convertir un resultado de búsqueda o instrucciones de un `SKILL.md` en permiso para instalar o ejecutar nada.

## Decisión

- Separar **descubrimiento e inspección** (`scripts/skill_scout.py`) de **instalación/sincronización** (`scripts/sync.py`).
- La v0.3 inicial usa únicamente la API pública de GitHub y Python estándar; no añade servicios, claves obligatorias ni dependencias.
- `discover` busca repositorios potencialmente relevantes. Son **candidatos no verificados**, no coincidencias confirmadas de skills.
- `locate` enumera archivos `SKILL.md` realmente versionados en un repositorio público, resuelve `default_branch` a un **SHA completo de commit** y comunica si el árbol está truncado.
- `inspect` recibe la URL de un único `SKILL.md` en GitHub vinculada a un **SHA completo de commit**. Rechaza ramas o etiquetas mutables.
- `inspect --related` enumera archivos asociados del mismo directorio, analiza de forma estática un subconjunto acotado de scripts, referencias, assets y manifiestos, y reporta las omisiones explícitamente.
- Se obtiene el contenido como datos desde la API de GitHub, se limita su tamaño, se calcula SHA-256 y se registra repositorio, mantenedor, SHA del commit y blob, licencia declarada del repositorio y señales estáticas de riesgo.
- No se sigue redirección HTTP, no se admiten hosts arbitrarios y no se ejecuta contenido descargado, subprocesos, scripts ni instaladores.
- Los informes JSON siempre requieren **revisión humana**; ni la ausencia de señales ni el dato de licencia equivalen a aprobación.
- No se guarda ningún archivo en el registro, no se alteran configuraciones globales de Claude/Codex y no se habilita ninguna ruta de instalación de terceros.

## Límites y amenazas reconocidas

- La búsqueda genérica no verifica que cada repositorio tenga `SKILL.md`; `locate` confirma rutas, pero no valida el contenido ni identifica la licencia de cada archivo.
- El árbol recursivo y los archivos relacionados están sujetos a límites de tamaño, conteo y formato; cuando se truncan, la revisión queda parcial.
- El análisis es **heurístico**. Opcionalmente revisa algunos archivos de texto dentro del directorio de la skill, pero no ejecuta scripts, ni sigue enlaces externos, ni audita integralmente dependencias, historial o cadena de suministro.
- La licencia reportada es del repositorio y debe revisarse su alcance sobre el archivo concreto.
- La compatibilidad Claude Code/Codex queda explícitamente `not-verified`. Parsear el encabezado no sustituye probar el comportamiento de los clientes.
- La API sin autenticación tiene límites de uso y requiere Internet.
- Un `SKILL.md` hostil puede incluir *prompt injection*. Solo se procesa como dato; sus instrucciones no deben obedecerse durante revisión manual o resúmenes posteriores.
- No existe catálogo persistente, detector de actualizaciones ni integración automática con el instalador.

## Próxima iteración

Añadir fuentes oficiales/catálogos mediante adaptadores de lectura, profundizar en dependencias, licencias y materiales relacionados, disponer de un contrato de aprobación/versionado con registro de procedencia y pruebas de compatibilidad aisladas. Solo después de revisión humana se diseñará una promoción explícita hacia `registry/` y `scripts/sync.py`; por defecto seguirá siendo un dry-run.

## Verificación

Pruebas unitarias con respuestas simuladas en `tests/test_skill_scout.py` y `tests/test_skill_scout_inventory.py`, sin acceso a red. La suite completa de `tests/` se ejecutará en CI sobre Windows y Ubuntu. Se evita ejecutar código de terceros incluso en pruebas.
