# ADR-0001 — Portable Engineering Core

**Status:** Accepted (v0.1; consolidated into v0.2).

## Context

Claude Code and Codex support global guidance and personal skills, but use different file locations. Per-project configuration duplicates work and a mega-prompt wastes context. We need reusable engineering judgment and task-specific expertise.

## Decision

- Canonical policy: `core/ENGINEERING_CORE.md`.
- Provider-specific adapters: `adapters/claude.md` and `adapters/codex.md`.
- Installed global instructions: `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md`.
- Installed personal skills: `~/.claude/skills/` and `~/.agents/skills/`.
- Installer: standard-library Python, dry-run default, explicit apply, backups, managed markers and fail-closed skill conflict detection.
- Do not change application repositories or transmit their contents into this public hub.
- Avoid autonomous external skill installation and automatic production actions.

## Tradeoffs

The initial system is portable and inspectable, without a service, dashboard or remote runner. Global instructions are kept short. Installing a skill does not guarantee a model will invoke it, nor guarantee senior-level results. Skill upgrades initially require manual review because existing files are never silently overwritten.

## Follow-ups

Add a reviewed manifest with hashes and revision pins, native specialist agents, update monitoring, security evaluation and quality benchmarks. Any automation should produce reviewable proposals before applying changes.
