# ADR-0002 — Revisión y actualización segura de skills instaladas

**Estado:** Aceptado en v0.2.

## Problema

Las cuatro skills v0.1 ya están instaladas en los directorios globales del usuario. El instalador original evitaba sobrescribir cualquier `SKILL.md` con contenido diferente, lo cual impedía desplegar mejoras aprobadas sin reemplazos manuales inseguros.

## Decisión

- Mantener copias exactas de las cuatro skills aprobadas en `registry/baselines/v0.1/`.
- `scripts/sync.py` continúa en modo **dry-run predeterminado**.
- `--upgrade-skills` habilita **solo en el plan** actualizaciones de archivos que coincidan exactamente con el baseline v0.1 (no significa permiso de escritura).
- Únicamente `--apply` aplica el plan. Para actualizar skills se requieren **ambos** parámetros; con una sola opción no se sobrescriben versiones diferentes.
- Cualquier skill desconocida, modificada por el usuario o sin baseline reconocido bloquea toda la operación **antes de escribir**.
- Se crean respaldos con marca de tiempo de cada archivo actualizado; el instalador comprueba de nuevo que no haya cambiado desde el plan.
- El Hub no elimina skills, no modifica las skills ajenas, no ejecuta scripts externos ni consulta servicios remotos.

## Límites

- La operación es atómica por archivo, no como una transacción de todos los archivos: un fallo del sistema durante la aplicación puede dejar una instalación parcial. Respaldos y ejecuciones posteriores permiten recuperar; se reportará este límite.
- El reconocimiento se basa en **contenido exacto**, no solo el nombre de la skill. Un archivo legítimo con modificaciones o distinto formato de saltos de línea requiere revisión manual.
- La versión actual reconoce upgrades del baseline v0.1 a los archivos aprobados de esta rama. Una versión posterior requerirá nueva referencia versionada y pruebas de migración.
- No hay monitoreo periódico ni autoactualización. Cualquier actualización debe revisarse y autorizarse explícitamente.

## Seguridad y evolución

La source of truth es este repositorio versionado; al ser público no debe recibir material privado. Las futuras skills descargadas de GitHub requerirán análisis de procedencia, licencia, permisos, contenido y aprobación, y **nunca se ejecutarán automáticamente**.
